# af 波次自转开发制度 v1（2026-11-06，运营者裁定：消灭单一收卷瓶颈）

> 目标：一次规划、自派自收、异常才叫人。LLM 子代理只干「施工」与「规划」；
> 验收/合线/落账/收割**全部确定性**；主代理只处理红件与部署窗。

## 一、三件套

| 件 | 形态 | 职责 |
|---|---|---|
| **波次清单** `wave-XX.json` | 规划工作流一次产出（可 20+ 卡） | 每卡：task_id/债号/通道/allowed_paths/验收命令集/合线策略/ledger 坐标/mem_budget/异步标记 |
| **执行器** `tools/wave-runner.py` | cron `*/15` 驱动，flock 单写，幂等 | 对每笔任务**推进一步**（状态机见下）；Σmem_budget 超 anolis 45G/本机 3G 则排队（OOM 准入制） |
| **异常队列** `af-state/dispatch/exceptions.jsonl` | runner 红件落此 | 整点巡检 cron 只扫此队列+饱和度；绿件零打扰 |

状态机（复用 registry）：`queued→(占用闸)→dispatched→running→verifying→(绿)merge-check→merged→ledgered`；任一步红→`parked+异常队列`。

## 二、四通道（卡在清单里声明，runner 按通道派发）

1. **anolis-build**（cargo 构建轨，mem 6-10G/卡，上限 4 并发）：ssh nohup 或后台终端任务；验收=cargo test/clippy/strategies_check 全绿。
2. **local-api**（step/minimax，本机禁 cargo）：动态工作流子代理；验收=点名 gate 脚本/字节对账。
3. **bot-lane**（外部沙箱，异步）：先 `dispatch-registry.py add --state queued`（消「登记面不可证」）→ `bot-bridge.py --task` 发布（占用闸如实拦就换锚债或登记新债行，禁 --force）。
4. **GLM/start-plan**（免费窗内）：同 local-api 通道换模型。

## 三、自动收卷四路（全部无需主代理）

| 路 | 机制 | 绿判据（确定性） |
|---|---|---|
| 本地/工作流施工 | runner 轮询完成→跑卡面**验收命令集** | 命令退出码+期望串 |
| bot 通道交卷 | **收割 sweep**：cron `*/20` 扫 `gov:submissions/` 新件→`bot-reclaim.sh` 全链 | G-JUDGE GREEN→audited-green-content 自动 absorb；STALE_RED/RED→异常队列 |
| 合线 | merge-check 树（三分支今夜范式）：`--no-ff` 合入→fmt+strat+全量 test+clippy→FF push | 退出码全 0；**feature 分支须显式 refspec 取回**（origin fetch 面窄化教训） |
| 落账 | 回写范式（核销批 difflib 证明）：只翻状态格+行尾 append 依据句、整文件先备 | `wc -l` 不变 + append-only opcodes + 点名行 diff 计数 |

## 四、主代理只现身于

① 异常队列红件裁决；② 部署窗（正本换码/gov 手术）；③ 波次清单的**签发**（每波一次）。
其余时间主会话可以沉默——开发不停。

## 五、OOM 准入账本（硬约束）

- anolis：Σmem_budget ≤ 45G（125G 的 36%），cargo 并发 ≤4；
- 本机（14G，昨夜 21:19 真 OOM）：**cargo 永禁**；只允许 API 轨+门禁（≈2G）；solar 训练另一会话固定占 ~18% 不排程；
- gov：小件后端手术，单卡 ≤2G。

## 六、已知坑登记（制度内消化）

1. origin fetch refspec 只 product/main → 合线前必须显式 refspec 取 feature；
2. 后台脚本禁裸 `set -e`（预期失败清理命令会中止全链）→ 分段守卫；
3. 台账无行的债号占用闸 fail-closed BLOCK → 派卡前置=登记债行或换锚；
4. dev 型 bot 卡禁项置顶「判官/门/判据件一改即拒收」（rt-e82/83 双案）。
