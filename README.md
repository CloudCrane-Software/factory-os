# factory-os · 黑灯工厂 OS 本体

工厂 OS（编排层）的在役件仓库：门禁与产线脚本、账本三件套、波次清单与自转制度。

**这是代码与账本的家，不是工作区的家。** 工作区（计划、状态、观测、内核种子仓 af/）不入本仓；
本仓只收「在役、可执行、可复现」的面。推送前过 `bot-scrub.py` fail-closed 闸（见下）。

## 二、git 历史 = append-only 证明

**本仓的 git 历史自建仓起承担 append-only 证明。**

账本三件套是只追加不改写的活文档（`wc -l` 不变 + append-only opcodes + 点名行 diff 计数
是既有回写范式）。它们过去的追加散落在工作区文件系统里，无历史可追溯；自进入本仓起，
每一次追加都由一次 commit 承载——commit 序列即不可篡改的追加序列。

因此：

- **不 force push、不 `reset --hard`、不动历史记录**（方案 §八 执行约束，全部继续有效）。
- 账本件的修改只允许「翻状态格 + 行尾 append 依据句」，且整文件先备；改完即 commit。
- 判官面（门禁件、判据件）由仓级 CODEOWNERS 锁给 `@feasy898`：工人 App 的 PR 改这些路径
  直接被保护规则拒——G-JUDGE 从「事后闸红」升级为「合不进去」。

## 四、出仓闸（推送前必跑）

```bash
python3 -I <bot-scrub.py 路径> . --out <树外报告.json>
```

`rc=0` 才可推送；`rc=1`（命中或覆盖不全）与 `rc=2`（结构失败）一律拒发。闸的内核复用
`tools/mirror-disclose.sh` 的 18 模式 + G-13 线性实现，单文件 30s 预算，二进制/非 UTF-8
一律登记为未覆盖面（fail-closed，不静默跳过）。本仓全公开，secret 绝不入 git——只记
指纹 + 路径。
